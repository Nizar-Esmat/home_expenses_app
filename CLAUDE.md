## Architecture

**BudgetBuddy** is a fully offline, local-first personal finance app built with React Native + Expo SDK 54, TypeScript, and `expo-sqlite`. There is no backend.

### Routing — Expo Router (file-based)

`app/` contains screens. The root `app/_layout.tsx` wraps the app with `GestureHandlerRootView → SafeAreaProvider → ThemeProvider → DialogProvider → Stack`.

`app/(tabs)/_layout.tsx` uses a **custom floating tab bar** (not the native `Tabs` component) wrapping `MonthProvider`. Tabs navigate to Home, Statistics, and Settings.

Modal screens (`add-expense`, `add-income`) are presented via `router.push()`.

### Database — SQLite (`expo-sqlite`)

**File:** `budgetbuddy.db` · **Schema version:** `PRAGMA user_version` (currently 3)

| Table | Purpose |
|---|---|
| `settings` | User preferences: themeMode, colorPalette, currency |
| `accounts` | Cash/bank/e-wallet accounts with balances |
| `categories` | Expense categories with emoji, color, isDefault |
| `transactions` | Unified table for expenses and incomes (`type = 'EXPENSE' \| 'INCOME'`) |
| `transaction_items` | Sub-items for multi-category transactions |
| `transfers` | Inter-account transfers with optional fees |

**Singleton:** `getDb()` in `src/services/database/client.ts` returns the single DB instance and runs schema creation/migrations on first call.

**Critical conventions:**
- **Money is stored as integer minor units (cents):** always use `toMinorUnits()` / `fromMinorUnits()` from `src/services/database/helpers.ts`
- **Booleans are INTEGER:** compare with `=== 1` / `=== 0`, never `=== true`
- **Migrations are destructive:** when `user_version < SCHEMA_VERSION`, financial tables are dropped and recreated — all user data is wiped. Take care when changing `SCHEMA_VERSION`
- Default currency is `EGP` (hardcoded in `client.ts`)

All database modules are re-exported from `src/services/database/index.ts`.

### State Management

No Redux, Zustand, or similar. State lives in three places:

1. **SQLite** — source of truth for all financial data
2. **React Context:**
   - `ThemeContext` (`src/theme/ThemeContext.tsx`) — dark/light mode + one of 9 color palettes
   - `MonthContext` (`src/contexts/MonthContext.tsx`) — shared `selectedMonthKey` across tab screens
3. **Local `useState`** — each screen manages its own loading, data, and UI state

### Data Loading Pattern

Screens reload data from SQLite every time they come into focus:

```typescript
useFocusEffect(
  useCallback(() => {
    loadData();
  }, [dependency])
);
```

### Theme System

`useTheme()` returns `{ colors, isDark, colorPalette }`. All UI colors must come from this hook — never hardcode colors. Nine palettes are defined in `src/theme/colors.ts` (grey, green, blue, purple, orange, red, teal, pink, yellow).

### Babel

`babel.config.cjs` sets `assumptions: { superIsCallableConstructor: true }` for Hermes compatibility. Required plugins: `babel-preset-expo`, `react-native-worklets-core/plugin`, `module-resolver`.

## Key Gotchas

- `android/` and `ios/` are in `.gitignore` — native directories are generated by Expo, not committed
- `*.db` files are gitignored — no SQLite files in the repo
- The `app/` screens are thin shells; actual logic lives in `src/screens/`
- Backup/restore (JSON export/import) is implemented in `src/services/sync.ts`
